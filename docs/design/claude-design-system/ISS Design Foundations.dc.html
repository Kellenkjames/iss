01 — Typography

Two families, no more. IBM Plex Sans carries all interface text — it reads calmly at both display and dense table sizes. IBM Plex Mono is reserved for anything literal: identifiers, code, timestamps, token names. Distinguishing "written for a human" from "written by the system" is itself a hierarchy signal (Philosophy §04).

TokenSize / LineWeightUsage
type.display28px / 1.25600Page titles only, one per screen
type.heading18px / 1.35600Section headings
type.subheading14px / 1.4600Group labels, card titles
type.body14px / 1.5400Default interface and table text
type.small12px / 1.4400Metadata, timestamps, helper text
type.micro11px / 1.3500Overline labels, badges — uppercase, tracked
type.mono13px / 1.5400IDs, code, token references (IBM Plex Mono)

02 — Semantic color system

Color is the last hierarchy signal, so the palette stays small: one cool neutral scale for structure, one accent for interactive/selected state, and four status hues sharing a single chroma and lightness so none reads as more "important" than another by virtue of intensity.

Rules: status hues never appear as decoration — only on the specific element they describe (a badge, a row indicator). Accent marks exactly one interactive or selected state per view. Text and surface tokens are used by role, never by literal hex — a component asks for text.muted, not "gray."

04 — Layout & grid

A 12-column grid with an 24px gutter underlies all workspace layouts. Three container widths cover the platform's needs — dense data views default to full-bleed within the app shell rather than a centered reading column, since ISS is a working tool, not a document.

TokenWidthUsage
container.narrow720pxForms, settings, single-record detail
container.standard1120pxDefault content column
container.full100% of shellDashboards, tables, workspaces

05 — Elevation

Elevation communicates layering, not decoration — used only where the interface genuinely stacks (drawers, menus, modals over a workspace). Shadows stay low-contrast and cool-toned so they read as depth, not as emphasis.

elevation.0 — flat
elevation.1 — card
elevation.2 — popover
elevation.3 — modal

06 — Motion

Motion is functional, per Philosophy §06 — it confirms cause and effect, never performs. Durations are short; easing favors deceleration so movement feels settled rather than bouncy.

TokenValueUsage
motion.instant0msValue changes in tables, live counters
motion.fast100ms · ease-outHover, focus, toggles
motion.base160ms · ease-outDrawers, dropdowns, tab switches
motion.slow240ms · ease-in-outModal enter/exit, page transitions

All durations respect prefers-reduced-motion by dropping to motion.instant.

07 — Accessibility

Accessibility is specified at the foundation layer so no component can be built without it:

Contrast. Body text meets 4.5:1 against its surface at minimum; text.muted is only used at ≥14px where 3:1 still applies.
Focus. Every interactive element gets a visible 2px accent-colored focus ring, never suppressed, never color-only.
Never color-only. Status is always paired with a label or icon shape — color reinforces, it doesn't carry the information alone.
Target size. Interactive targets are at least 32px in dense/table contexts, 44px in any touch-capable surface.

08 — Design tokens

All values above ship as CSS custom properties under a single --iss- namespace, so Lit components consume them with zero build-time dependency and Angular theming layers on top without overriding component internals.

CategoryNaming patternExample
Color--iss-color-{role}--iss-color-accent
Type--iss-font-{token}--iss-font-body-size
Space--iss-space-{n}--iss-space-4
Radius--iss-radius-{n}--iss-radius-2
Elevation--iss-elevation-{n}--iss-elevation-2
Motion--iss-motion-{speed}--iss-motion-base

Tokens are versioned with this document. A breaking change to a token value is a major version bump of the Design Platform, communicated before any dependent product adopts it — consistent with the "systems precede products" principle this platform is built on.
